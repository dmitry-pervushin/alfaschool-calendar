# Alfa School Calendar для Home Assistant

Пользовательская интеграция создаёт отдельный календарь занятий для каждого
аккаунта непосредственно в Home Assistant. Настройка через интерфейс: логин,
пароль и интервал опроса. Имя ученика определяется автоматически по профилю.
Внешний скрипт, HTTP-сервер и файл ICS не нужны.

## Установка

Требуется Home Assistant **2026.11 или новее**. Проверено на 2026.11.1.

1. В терминале Home Assistant выполните:

   ```bash
   git clone https://dmitry-pervushin@github.com/dmitry-pervushin/alfaschool-calendar.git /config/alfaschool-calendar
   mkdir -p /config/custom_components
   ln -s /config/alfaschool-calendar/custom_components/alfaschool /config/custom_components/alfaschool
   ```

   Репозиторий приватный. При запросе пароля GitHub введите Personal Access Token
   с правом **Contents: Read-only** для этого репозитория. Обычный пароль GitHub
   для Git не подходит. Токен не нужно включать в URL или команду.
   Для обновления Git может снова запросить токен.

   Ссылка использует путь `/config`, одинаковый для терминала и контейнера HA Core.
   Если интеграция уже установлена копированием, сначала переместите её папку
   `/config/custom_components/alfaschool` в резервную копию вне `custom_components`.
   Команда `ln -s` предназначена для первой установки и не заменяет существующую папку.

   Альтернатива: скачайте ZIP из [Releases](https://github.com/dmitry-pervushin/alfaschool-calendar/releases)
   и распакуйте его в `/config`, либо скопируйте папку `custom_components/alfaschool`
   в `/config/custom_components/alfaschool`.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Alfa School**.
4. Введите логин и пароль школы. Имя ученика будет прочитано из профиля автоматически.
   Укажите интервал обновления в часах:
   `24` (по умолчанию), `8`, `4` или другое целое число от 1 до 24.
   Значение `0` — **никогда не обновлять автоматически**, только вручную.

Создаётся одна сущность календаря на аккаунт. Название — **Alfa School — Имя из профиля**.
Порядок имени и фамилии сохраняется таким, как на сайте. Если сайт не сообщает имя,
используется логин. Для другого аккаунта добавьте ещё
одну запись интеграции.
Вход и чтение текущего месяца проверяются до сохранения настроек.

Home Assistant создаёт `entity_id` из названия при первом добавлении:
например, имя `Dmitry` даёт `calendar.alfa_school_dmitry`, а `Anna` —
`calendar.alfa_school_anna`. Кириллица транслитерируется средствами HA.
При совпадении имён HA добавляет суффикс (`_2` и т. д.); аккаунты, сессии
и занятия остаются раздельными.

Имя ученика можно менять через **Настроить**; пустое поле возвращает имя из профиля.
У ранее подключённых аккаунтов без сохранённого имени оно определяется при
первой успешной загрузке после обновления. Ручное имя имеет приоритет.
При этом существующие `entity_id`
и `unique_id` сохраняются, чтобы не ломать автоматизации. Уже установленные
календари также сохраняют прежний `entity_id`. Если имя сущности или её ID
изменены вручную в HA, интеграция сохраняет эти настройки пользователя.

Для приватного репозитория здесь описаны установка через авторизованный Git
и скачивание ZIP из Releases после входа в GitHub.

Обновление установки через Git:

```bash
git -C /config/alfaschool-calendar pull --ff-only
ha core restart
```

Для первой установки тоже можно выполнить `ha core restart`, затем добавить
**Alfa School** через интерфейс. Команда `ha` доступна в терминале HA OS;
для HA Container перезапустите контейнер своим обычным способом.

## Обновления и работа календаря

- Первый опрос выполняется при загрузке интеграции, затем каждые N часов.
  При значении `0` периодический опрос отключён: после начальной загрузки
  расписание обновляется только вручную. После перезапуска HA начальная
  загрузка выполняется снова.
  Интервал меняется через **Настроить** у записи интеграции и применяется
  с её перезагрузкой. Внешняя автоматизация опроса не требуется.
- Основное окно: от 30 дней назад до 180 дней вперёд. При открытии календаря
  за другой период нужные месяцы загружаются один раз, затем обновляются
  вместе с основным окном до перезагрузки интеграции. Повторное открытие
  уже загруженного периода читает кэш.
- Текущее/следующее занятие, календарная панель, `calendar.get_events`, карточки
  и календарные триггеры HA используют одну сущность. HA отслеживает начало
  и конец занятия независимо от интервала опроса школы.
- Московское время сайта сохраняется с часовым поясом и отображается в часовом
  поясе HA. Длительность, предмет и преподаватель берутся из карточки занятия.
- UID формируется из ID занятия и сохраняется при изменении даты/времени.
  Удалённые записи исчезают при следующем успешном опросе; явно отменённые
  занятия исключаются. Состояние с сайта сохраняется в описании.
- Блоки «Занятый период» не являются занятиями. Повторения не генерируются:
  интеграция показывает только записи, опубликованные школой.
- При сетевой ошибке или изменении формата страницы календарь получает состояние
  `unavailable`. Последний снимок остаётся в памяти, но не выдаётся как актуальный.
  После восстановления связи следующий успешный опрос восстановит календарь.
- Если пароль перестал подходить, HA предложит повторный вход. Удалять
  интеграцию и создавать календарь заново не нужно.
- Календари доступны для чтения. Создание, перенос и отмена занятий выполняются
  в личном кабинете школы.

Если открыта новая область календаря, которой нет в кэше, её первичная загрузка
выполняется сразу независимо от интервала, кроме режима `0`. В ручном режиме
открытие календаря не обращается к школе: отсутствующие месяцы добавляются
к следующему ручному обновлению. Пока они не загружены, события для них не показываются.
При ошибках HA также может повторять
первоначальную настройку. Интервал N часов относится к обычному фоновому опросу.

Для принудительного обновления используйте действие `homeassistant.update_entity`
с фактическим entity_id календаря.

```yaml
action: homeassistant.update_entity
target:
  entity_id: calendar.alfa_school_dmitry
```

## Карточка календаря

В существующей `custom:outlook-calendar-card` новый календарь появляется
автоматически, если список календарей не ограничен. Для явного списка:

```yaml
type: custom:outlook-calendar-card
calendars:
  - entity: calendar.alfa_school_dmitry
```

## Напоминание за 15 минут

```yaml
alias: Напомнить о занятии Alfa School
triggers:
  - trigger: calendar
    entity_id: calendar.alfa_school_dmitry
    event: start
    offset: "-00:15:00"
actions:
  - action: persistent_notification.create
    data:
      title: Скоро занятие
      message: "{{ trigger.calendar_event.summary }}"
mode: parallel
```

Изменения расписания обнаруживаются только при очередном опросе. При интервале
24 часа срочный перенос может стать известен HA с задержкой до суток.

## Учётные данные

Логин и пароль вводятся в HA и хранятся в его стандартной записи конфигурации.
Интеграция обращается только к `https://my.alfaschool.ru`, не записывает пароль
в журнал и не публикует расписание через `/local/`. Cookies хранятся в памяти
в отдельной сессии каждого аккаунта. Доступ к аккаунту используется только
для входа и чтения страниц расписания.

Чтобы удалить интеграцию: **Настройки → Устройства и службы → Alfa School → Удалить**.
После выгрузки останавливаются опрос и сессия аккаунта.

## Разработка

```bash
python3.14 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/ruff check custom_components tests
.venv/bin/ruff format --check custom_components tests
```

Тесты запускают настоящий HA во временном каталоге и локальный HTTP-сервер,
изображающий школу. В CI реальные логин и пароль не используются.
Проверяются вход, cookies, ошибки, часовой пояс, дубликаты, отмены, пересечение
границ периода, текущие/следующие события, кэш, создание сущности, настройка
интервала, выгрузка и повторный вход.

Alfa School не предоставляет использованный здесь документированный API:
интеграция читает HTML личного кабинета. Изменения сайта могут потребовать
обновления парсера. Данные сайта на момент проверки: будущих занятий нет;
история октября 2025 содержит два занятия.

Старый автономный экспортёр ICS оставлен отдельно: [инструкция](EXPORTER.md).

Официальная документация HA:
[календари](https://developers.home-assistant.io/docs/core/entity/calendar/),
[опрос данных](https://developers.home-assistant.io/docs/integration_fetching_data/).
